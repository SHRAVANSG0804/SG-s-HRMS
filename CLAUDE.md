# Tarang HR: HRMS for Konkan Coastal Foods

A web HRMS for a 180-person Indian company with two locations: the Panaji head office and the Verna plant, both in Goa.
It has three modules, Employee Master, Attendance and Leave, plus an "Ask HR" AI agent that works by calling tools.
Payroll is out of scope. The app only produces the month-end attendance CSV for the payroll vendor.

## Current stage

## Source of truth

- Architecture, data model, access control: `ARCHITECTURE.md`.
- Screens, colours, components, status colours: `DESIGN.md`. **Follow DESIGN.md.** Never invent new colours or status styles.
- Out-of-scope features (payroll, PF/ESI/TDS, recruitment, biometrics/GPS, shifts, mobile app, multi-tenant) are never built.

## Stack
Next.js (App Router, TypeScript) on Vercel · Supabase Postgres with RLS · Clerk (native Supabase integration; RLS reads `auth.jwt()->>'sub'`) · Gmail SMTP via Nodemailer · Vercel AI SDK with Gemini Flash (Groq fallback) · Tailwind + shadcn/ui · Zod · Vitest.
Free tiers only.

## Rules that are never broken
- **All times are IST (Asia/Kolkata).** Use only the helpers in `src/lib/time/ist.ts`. Never use `new Date().getDate()`, a time-zone-less `toLocaleDateString()`, or `toISOString().slice(0,10)` for business dates. In SQL, today is `(now() AT TIME ZONE 'Asia/Kolkata')::date`.
- **Every role check runs on the server.** Every server action and route calls `requireEmployee()` / `requireHR()` / `requireManagerOf()` / `requireSelfOrHR()`. Hiding a button is never the check.
  - Store only `is_hr_admin`. Manager = has at least one active direct report. Never read roles from Clerk metadata or the URL.
- **Sensitive data:**
  - PAN, Aadhaar and bank numbers are masked everywhere, including CSVs: `ABCDE****F`, `XXXX XXXX 1234`, last 4 digits of the account.
  - Raw values come only from the HR-only, logged Reveal function. Aadhaar is never revealed.
  - None of these fields ever reaches the AI model.
- **Never store the available balance.** Compute it as opening + accrued − used − pending.
- **Integrity lives in the database:** unique `(employee_id, attendance_date)`, a no-overlap exclusion on leave, a reporting-cycle trigger, `approver_id <> employee_id`, and the employee code generated by a sequence.
- **The agent never acts on its own.** Every write it makes is a draft that the user confirms. It has a maximum of 5 tool calls per question, and every call is logged to `agent_log`. Numbers come only from tools; policy answers come only from the stored policy text.
- **Never commit secrets.** Keys go in `.env.local` (git-ignored) and Vercel env vars. `.env.example` keeps blank values.
- **Never run database resets or destructive migrations, or commit `.env*` files, without explicit approval.**

## Folder layout
```

src/lib/rules/      PURE functions: workingDays, dayStatus, proRate, accrual, masks (no I/O)

src/lib/time/ist.ts the only place that knows about time zones

tests/              rules/, leave/, attendance/, security/, agent-prompts/ (15+ attack prompts)
```

## Working style
- Write the test first from the testing checklist in the brief, then implement until it passes.
- Business rules go only in `src/lib/rules/` and are reused by screens, server actions, the CSV and agent tools. They are never duplicated.
- Run `npm test` before every commit, and run the time-zone tests with `TZ=UTC` and `TZ=America/Los_Angeles`.
- Small commits with clear messages, pushed after each checkpoint.
- When I correct the same mistake twice, add the rule to this file.
